# LLM Analytics Product

Мини-продукт для аналитики данных с LLM: веб-интерфейс в формате чата, куда можно загрузить `CSV/Excel` или отправить текстовый запрос.  
При работе с датасетом LLM действует как агент: вызывает локальный Python-интерпретатор `execute_python`, считает метрики кодом по `pandas.DataFrame`, а затем возвращает вывод и графики.

**LLM, используемая в работе (текущая в `.env`):** `MiniMax M2.7` (`minimax/minimax-m2.7`)

## Что делает приложение

- принимает запрос в чат;
- поддерживает загрузку `csv/xlsx/xls` через кнопку-скрепку;
- может распознать таблицу, вставленную текстом;
- вызывает LLM через API;
- для анализа датасета заставляет LLM вызвать tool `execute_python`;
- показывает текстовый ответ потоком для запросов без датасета;
- строит графики в UI по JSON-спецификации, рассчитанной агентом через tool;
- хранит историю чатов отдельно по пользователю в кэше.

## Как работает пайплайн

1. Пользователь отправляет текст и/или файл.
2. Таблица читается в `pandas`, валидируется размер и формат.
3. Если датасет подключен, запускается агентный цикл `LLM -> execute_python -> LLM`.
4. LLM пишет Python/pandas-код для tool `execute_python`; внутри tool доступен `df`.
5. Tool выполняет код в отдельном процессе, возвращает `answer`, `metrics` и `charts`.
6. Финальный ответ формируется LLM только по результатам tool.
7. Спеки графиков нормализуются и `Plotly` отрисовывает их в чате.

## Технические особенности

### 1) Потоковый ответ (streaming)

- Реализован в `llm_stream.py` (`SSE`-чтение `data:` чанков).
- Для запросов без подключенного датасета в чате показывается «живой» набор текста.
- Если stream не поддерживается или пришёл пустой поток:
  - есть автоматический fallback на обычный API-запрос;
  - есть дополнительные авто-попытки (без ручного повторного ввода).

### 2) Агентный анализ через Python tool

- Для запросов по датасету используется локальный tool `execute_python` в `code_interpreter.py`.
- LLM обязана вызвать tool перед ответом по данным.
- Код выполняется над реальным `pandas.DataFrame df`, а не над заранее подставленным summary.
- Tool возвращает вычисленные метрики, текстовый черновик `answer` и спецификации графиков `charts`.
- Если провайдер не поддерживает OpenAI-compatible `tools`, включается совместимый режим: LLM сначала генерирует код для `execute_python`, приложение выполняет tool, затем LLM формирует финальный ответ по результату tool.

### 3) История и кэш (24 часа)

- История хранится в памяти процесса через `st.cache_resource`.
- TTL кэша: `24 * 60 * 60` секунд.
- Данные хранятся отдельно по `user_id`.
- `user_id` берётся из query-параметра `uid` (если его нет, создаётся автоматически).
- База данных не используется.

### 4) Графики в UI

- Агент возвращает JSON-спеки графиков через результат `execute_python`.
- Отрисовка выполняется локально через `plotly.express`.
- Поддерживаемые типы: `bar`, `line`, `scatter`, `pie`, `histogram`.
- Есть нормализация:
  - авто-подстановка метрики в `y`, если модель вернула «пустой» spec;
  - защита от «бесполезных» графиков `count`, когда нужна реальная метрика.

## Что где находится

- `app.py`
  - Streamlit UI;
  - чат, загрузка файлов, история диалогов;
  - связывает текстовый поток и построение графиков.
- `llm_client.py`
  - загрузка конфига из `.env`;
  - запросы к LLM API;
  - агентный цикл с вызовом tool;
  - fallback для провайдеров без native tool calling.
- `llm_stream.py`
  - потоковый режим (SSE) для ответа модели.
- `analytics_core.py`
  - нормализация спеков графиков;
  - fallback-логика по графикам;
  - фильтрация по типу/количеству графиков;
  - сборка `plotly`-фигур.
- `code_interpreter.py`
  - локальный Python-интерпретатор `execute_python`;
  - выполнение pandas-кода в отдельном процессе с таймаутом.
- `chat_cache.py`
  - хранение истории и очистка просроченного кэша.

## Переменные окружения (`.env`)

Пример в `.env.example`.

```env
LLM_PROVIDER_LABEL=Example Provider
LLM_API_BASE_URL=https://api.example.com/v1
LLM_CHAT_COMPLETIONS_PATH=/chat/completions
LLM_MODEL=provider/model-name
LLM_API_KEY=sk-example-key

LLM_TIMEOUT_SECONDS=90
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=1200
LLM_MAX_CONTEXT_ROWS=30
LLM_MAX_CHARTS=3
LLM_AGENT_MAX_STEPS=5
LLM_CODE_TIMEOUT_SECONDS=12
```

### Комментарии по настройке

- `LLM_MAX_TOKENS` — длина ответа модели.
- `LLM_MAX_CONTEXT_ROWS` — используется для старого текстового режима без агентного анализа.
- `LLM_MAX_CHARTS` — верхний лимит графиков за ответ (дополнительно ограничивается текстом запроса).
- `LLM_AGENT_MAX_STEPS` — максимум шагов агентного цикла с tool.
- `LLM_CODE_TIMEOUT_SECONDS` — таймаут выполнения одного вызова Python-интерпретатора.

## Запуск проекта

### 1) Локально (venv)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` и запустите:

```bash
streamlit run app.py
```

Открыть:

```text
http://localhost:8501
```

### 2) Через Docker (локально)

```bash
docker compose up --build
```

Открыть:

```text
http://localhost:8501
```

## Частые проблемы

1. `В .env не задано обязательное поле ...`
   Проверьте заполнение `.env`.

2. `Модель не вернула текстовый ответ` / пустой ответ
   В проекте есть авто-fallback и авто-retry, но при нестабильном API провайдера могут быть деградации.

3. История пропала
   Кэш хранится в памяти процесса. При перезапуске контейнера/процесса история сбрасывается.
